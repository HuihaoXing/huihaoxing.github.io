Case study, applied AI

Each lead took 15 minutes of research. Can AI do it without acting on its own?

A pre-launch B2B food brand needed importers and specialty distributors, with one person owning everything technical. I designed and built the prospecting system that finds them, researches them and drafts the outreach.

First

The naive version fails twice.

Cost inversion. Deep research is the expensive step; running it on every scraped candidate spends the most on the leads you know least about.

Trust. Auto-sent AI outreach reads as spam, and in food import, a relationship business, a bad first touch closes the account.

So the design question was not how much the model could do, but what it must never do.

01

Find candidates.

Deterministic code queries the Google Places API and de-duplicates against every lead already seen. No model calls, so widening the candidate pool costs almost nothing.

02

A person decides.

A reviewer keeps or passes each candidate. Model spend is unlocked only by that decision, which makes the human the budget allocator rather than a final rubber stamp.

03

Research with sources.

Approved leads are enriched by Claude or OpenAI with provider-hosted web search. Every claim carries a public citation; anything unverifiable stays blank.

The model then returns structured verdicts a reviewer can check: buyer or competitor, product-spec fit, and the reason.

Blank beats plausibleAn honest gap costs a follow-up question. A confident hallucination in a first email costs the relationship.

04

A draft, never sent.

A separate model call writes the outreach from saved research, so a prompt change never pays for research twice. Approving opens a prefilled draft in the reviewer’s own mail client; the app holds no mail credentials and has no send path.

Design

Where the models sit, and what bounds them.

  • No model where code will do. Discovery and de-duplication are deterministic.
  • Per-step model choice. Each stage runs on the lowest-cost Claude or OpenAI model that meets the quality bar, switchable per run.
  • Structured output. Judgments return JSON against a schema, so every verdict is machine-checkable and reviewer-scorable.
  • Bounded cost. A pinned cap on web searches per call, prompt caching on the stable system prompt, and a billing log with a monthly budget cap.
  • Tools, not a script. The pipeline is also an MCP server, so an agent can call each stage with the gate and limits enforced in code rather than in the prompt.
  • Measured. Each run logs reviewer-marked classification accuracy, review time per lead and cost per stage.

Result

2 to 5 minutes per lead, not 15.
